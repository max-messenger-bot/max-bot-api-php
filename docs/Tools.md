# Инструменты разработчика

Консольные утилиты для разработки, отладки и управления подписками находятся в папке [`bin`](../bin).

## Запуск

```sh
./bin/max-debug
```

Если прямой запуск недоступен (например, бит исполнения не установлен), запускайте через PHP:

```sh
php bin/max-debug.php
```

Ключ `-h` или `--help` выводит краткую справку по утилите без её запуска:

```sh
./bin/max-debug --help
```

## Установка как отдельного проекта

Если запуск инструментов из вашего проекта затруднён (нет доступа к папке `bin`, конфликт зависимостей и т.п.),
установите пакет как отдельный автономный проект:

```sh
composer create-project max-messenger-bot/max-bot-api-php my-bot-tools
cd my-bot-tools
```

После этого все инструменты доступны напрямую из корня проекта:

```sh
./bin/max-debug
./bin/max-subscribe
./bin/polling-to-webhook
```

Или через PHP:

```sh
php bin/max-debug.php
php bin/max-subscribe.php
php bin/polling-to-webhook.php
```

Настройте токены доступа один раз в `dev/.max-tokens` — и больше не вводите их при каждом запуске:

```sh
cp dev/.max-tokens.example dev/.max-tokens
```

## Настройка токенов доступа

Чтобы не вводить токен доступа при каждом запуске, создайте файл `.max-tokens`. Инструменты ищут его в корне проекта
и в папке `dev/` — это работает и при разработке самого пакета, и при установке пакета как зависимости.

```sh
# при разработке самого пакета
cp dev/.max-tokens.example dev/.max-tokens

# в проекте, который подключает пакет — в корне проекта или его папке dev/
cp vendor/max-messenger-bot/max-bot-api-php/dev/.max-tokens.example .max-tokens
```

Формат файла — одна запись на строку:

```
my-bot=ваш-токен-доступа
test-bot=другой-токен-доступа
```

При запросе токена инструмент предложит выбрать его из списка. Если файл не найден, инструмент подскажет,
где он искал и какой командой скопировать пример. `polling-to-webhook` не запрашивает токен,
если он задан в его конфигурации.

## Ручной интеграционный тест

Интерактивные сценарии проверяют публичные классы пакета на реальном боте. Они не входят в автоматический набор тестов.
Нужны зависимости для разработки, действующий токен и отсутствие Webhook-подписок. Ожидание события по умолчанию
длится до десяти минут. Параллельные процессы Long Polling допустимы.

На вопросы с ручным подтверждением отвечайте кнопками в MAX. Непройденные проверки записываются в отчёт;
если они есть, после завершения сценария процесс возвращает код `1`.

```sh
php tests/Manual/all-interaction.php

# либо отдельные части
php tests/Manual/bot-interaction.php
php tests/Manual/chat-setup-interaction.php
php tests/Manual/chat-messages-interaction.php
php tests/Manual/chat-members-interaction.php
php tests/Manual/chat-finish-interaction.php
php tests/Manual/channel-interaction.php
php tests/Manual/dialog-events.php
```

Основной сценарий `all-interaction.php` предлагает выбрать стартовый блок и запускает его вместе со всеми
последующими с одним токеном. Ошибки проверок записываются в итоговый список.
Сценарий требует двух тестовых пользователей, нового группового чата и тестового канала.

`bot-interaction.php` проверяет личный диалог: текст и разметку Markdown/HTML, эмодзи, стикеры, контакты, геолокацию,
команды, callback, удаление сообщений и все типы кнопок, кроме `open_app`. Сценарий изменяет список команд бота,
а затем очищает его, не восстанавливая исходные команды. При необходимости сохраните их заранее.

Для группового чата есть четыре отдельных сценария:

- `chat-setup-interaction.php` — добавление и удаление бота, права и получение сообщений;
- `chat-messages-interaction.php` — свойства и сообщения чата, действия бота;
- `chat-members-interaction.php` — участники и права;
- `chat-finish-interaction.php` — удаление чата пользователем.

При общем запуске сценарии работают с одним чатом. При отдельном запуске одного из последних трёх сценариев тест
просит отправить кодовую фразу в нужный чат и определяет его по событию сообщения. Бот должен быть администратором
чата с правом «Читать сообщения»; для отдельных проверок потребуются дополнительные права.

`channel-interaction.php` запускайте **только в тестовом канале** с включёнными комментариями. Добавьте бота
в канал без прав администратора, затем перешлите ему в личный диалог любой пост: тест определит ID канала по пересылке.
Сценарий проверяет права «Доступ к постам канала», «Писать посты», «Редактировать чужие посты»,
«Удалять чужие посты», «Закреплять посты», «Редактировать канал», «Добавлять и удалять подписчиков» и
«Назначать и удалять администраторов» и ждёт выдачи всех недостающих прав. Тест проверяет посты, комментарии,
закрепление, изменение и восстановление названия и описания канала. Исходное закрепление не восстанавливается.
Человек добавляет тестового подписчика, бот назначает и снимает его администратором, затем человек удаляет подписчика.
Бот проверяет отказ в повторном добавлении через API и пробует удалить подписчика. Ошибки этих проверок записываются
в отчёт. Если сценарий прерван, удалите оставшиеся объекты с префиксом `SDK` и проверьте название, описание,
закреплённый пост и права участников канала.

`dialog-events.php` проверяет отключение и включение уведомлений, очистку и удаление диалога,
остановку и повторный запуск бота. Поэтому эта часть идёт в конце общего прогона.

Для сообщений, отправленных через вспомогательные методы сценариев, тест сравнивает `getRawData()` ответа
с ожидаемыми данными. Некоторые значения, например ID сообщения и время, берутся из ответа. Отдельные проверки
также читают сообщения и комментарии повторно. Посторонние события и неверные действия пользователя пропускаются
во время ожидания нужного события.

Сценарии пользуются `MaxApiClient`, моделями и обработчиками пакета.
Для сценариев недостаточных прав проверяются HTTP-код и тело ответа, доступные через исключение.
Проверка загрузки медиа требует отдельного пакета загрузки и тестовых файлов.

## Инструменты

### max-debug

Выводит в режиме реального времени события, поступающие боту через **Long Polling**.

Используется для наблюдения за входящими событиями без написания обработчика.
Если одновременно запущен другой обработчик **Long Polling**, оба будут получать события параллельно.

### max-subscribe

Регистрирует подписку **Webhook**. Последовательно запрашивает:

1. **Токен доступа**.
2. **URL** — адрес Webhook-endpoint (только `https://`, без порта).
3. **Типы событий** — номера из показанного списка через запятую или `all` для всех.
4. **Secret** — кодовое слово для заголовка `X-Max-Bot-Api-Secret` (5–256 символов, `A-Za-z0-9_-`).

После сохранения проверяет, что подписка действительно появилась на сервере.

### max-subscribes

Выводит список всех активных подписок **Webhook** с датой создания, версией API и типами событий.

### max-unsubscribe

Выводит список подписок и позволяет удалить выбранную. Перед удалением запрашивает подтверждение (`yes`).

После удаления выводит обновлённый список подписок.

### polling-to-webhook

Получает события методом **Long Polling** и передаёт каждое из них скрипту-обработчику через **php-cgi**,
эмулируя входящий **Webhook**-запрос.

В отличие от прямой обработки в цикле **Long Polling**, скрипт-обработчик запускается заново для каждого события —
поэтому после правки кода обработчика не нужно перезапускать скрипт.

Конфигурация задаётся в файле `.max-polling-to-webhook.conf`. Скрипт ищет его в корне проекта,
который подключает пакет, и в папке `dev/` этого проекта (именно в таком порядке). Это работает
и при запуске из самого пакета, и при установке пакета как зависимости (`vendor/bin/polling-to-webhook`).

```sh
# в корне проекта
cp vendor/max-messenger-bot/max-bot-api-php/dev/.max-polling-to-webhook.conf.example .max-polling-to-webhook.conf

# либо в папке dev/ проекта
cp vendor/max-messenger-bot/max-bot-api-php/dev/.max-polling-to-webhook.conf.example dev/.max-polling-to-webhook.conf
```

При разработке самого пакета корень проекта совпадает с корнем репозитория:

```sh
cp dev/.max-polling-to-webhook.conf.example dev/.max-polling-to-webhook.conf
```

Если конфиг не найден, скрипт выведет список проверенных путей и готовые команды для копирования примера.

Параметры конфигурации:

| Параметр              | Описание                                                                                        |
|-----------------------|-------------------------------------------------------------------------------------------------|
| `MAXBOT_ACCESS_TOKEN` | Токен доступа бота для Long Polling (необязателен — если не задан, будет запрошен интерактивно) |
| `SCRIPT_FILENAME`     | Полный путь к скрипту-обработчику (webhook handler)                                             |
| `DOCUMENT_ROOT`       | Корневая папка сайта, внутри которой лежит скрипт-обработчик                                    |
| `BIN`                 | Путь к `php-cgi` (необязателен, если он находится рядом с текущим PHP)                          |
| `MAXBOT_SECRET`       | Значение заголовка `X-Max-Bot-Api-Secret`                                                       |
| `REQUEST_URI`         | Адрес запроса. По умолчанию — путь скрипта относительно `DOCUMENT_ROOT`                         |
| `HTTP_HOST`           | Значение заголовка `Host`, можно с портом (`localhost:8080`). По умолчанию: `localhost`         |
| `SCHEME`              | Схема запроса: `http` или `https`. По умолчанию: `http`                                         |
| `REMOTE_ADDR`         | IP-адрес отправителя запроса. По умолчанию: `127.0.0.1`                                         |

#### Обработчик на Laravel или Symfony

Скрипту-обработчику передаётся окружение, достаточное для создания объекта запроса из глобального
контекста (`Illuminate\Http\Request::capture()`, `Symfony\Component\HttpFoundation\Request::createFromGlobals()`):
кроме тела запроса и заголовков задаются `REQUEST_URI`, `DOCUMENT_ROOT`, `SCRIPT_NAME`, `PHP_SELF`,
`SERVER_NAME`, `SERVER_PORT`, `SERVER_PROTOCOL`, `REQUEST_SCHEME`, `REMOTE_ADDR`, `HTTP_HOST` и `HTTP_ACCEPT`.

Если обработчик — фронт-контроллер фреймворка, укажите `REQUEST_URI`: иначе адресом запроса станет путь
самого фронт-контроллера (`/index.php`) и маршрут не будет найден.

```ini
SCRIPT_FILENAME=/var/www/app/public/index.php
DOCUMENT_ROOT=/var/www/app/public
REQUEST_URI=/api/max/webhook
HTTP_HOST=localhost
```

Секрет приходит в заголовке `X-Max-Bot-Api-Secret` — там, где его ждёт и настоящий Webhook-запрос.
