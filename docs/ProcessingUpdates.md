# Обработка обновлений

## Терминология

**Обновление** — это объект класса `\MaxMessenger\Bot\Model\Response\Update` или наследуемого от него класса.
Тип обновления содержится в поле `update_type`.

**Событие бота** — это объект класса, наследуемого от `\MaxMessenger\Bot\MaxBot\Event\BaseEvent`.

Согласно [документации API MAX](https://dev.max.ru/docs-api/objects/Update), бот не получает обновления
на собственные действия.

**По результатам тестов:** в каналах бот может получать обновления на собственные действия.

## Рекомендации

- Используйте [рекомендации официального API](https://dev.max.ru/docs-api/use-cases/event-notifications/).
- Когда вы настраиваете получение **обновлений** о действиях в чат-боте, используйте:
    - **Long Polling** — для разработки и тестирования.
    - **Webhook** — для production-окружения.
- Для сохранения обновлений используйте их исходные данные, а не PHP-сериализацию объектов.
  См. раздел [Сохранение и восстановление обновлений](#сохранение-и-восстановление-обновлений).

## Способы получения обновлений

### Long Polling

Этот способ можно использовать для получения **обновлений** при разработке и тестировании,
если ваш бот не подписан на Webhook. Для production-окружения рекомендуем использовать **Webhook**.

Метод использует долгий опрос (long polling).
Каждое обновление имеет свой номер последовательности.
Свойство `marker` в ответе указывает на следующее ожидаемое обновление.

Все предыдущие обновления считаются завершёнными после прохождения параметра marker.
Если параметр marker не передан, бот получит все обновления, произошедшие после последнего подтверждения.

Обновления можно получить и обработать одним вызовом `MaxBot::handleFromServer()`, но Вы также можете изучить
код метода и изменить любую его внутреннюю часть, все используемые внутри методы являются публичными.

- [Примеры обработки обновлений](Examples/ProcessingUpdates.md)
- Больше информации в [официальной документации](https://dev.max.ru/docs-api/methods/GET/updates)

### Webhook

Способ доставки обновлений через **Webhook** — основной механизм получения обновлений в production-интеграциях.
При активной подписке **Long Polling** не работает.

Webhook-endpoint должен возвращать HTTP 200 в течение 30 секунд.
Любой другой код ответа или превышение тайм-аута — ошибка доставки.

Если доставка не удалась, выполняется до 10 повторных попыток с экспоненциально растущим интервалом:

- 1-я попытка: через 60 секунд
- 2-я попытка: через 150 секунд (60 × 2,5)
- 3-я попытка: через 375 секунд (150 × 2,5)
- и так далее

- [Примеры обработки обновлений](Examples/ProcessingUpdates.md)
- Больше информации в [официальной документации](https://dev.max.ru/docs-api/methods/POST/subscriptions)

#### Безопасность Webhook-запросов

Параметр **secret** позволяет убедиться, что Webhook-запросы приходят от МАКС, а не от третьей стороны.

Если **secret** настроен, методы `MaxBot::readRequestContentFromGlobal()` и `MaxBot::readRequestContent()`
(а значит и `MaxBot::handleFromGlobal()` с `MaxBot::handleFromRequest()`) автоматически проверят его
в заголовке `X-Max-Bot-Api-Secret`. Это необязательный параметр, но его настоятельно рекомендуется указывать.

Если вы самостоятельно читаете и обрабатываете входящий запрос без встроенных механизмов SDK,
используйте `$bot->validateRequestHeaders()` для проверки его метода и заголовков,
а затем `MaxBot::validateRequestBody()` для проверки тела.
См. пример [Самостоятельная обработка Webhook](Examples/ProcessingUpdates.md#самостоятельная-обработка-webhook).

`MaxBot::validateRequestHeaders()` проверяет метод запроса, тип содержимого, длину содержимого и секрет, если он задан.
При некорректном методе или заголовках выбрасывается `BadRequestException`,
при несовпадении секрета — `InvalidSecretException`. При `setSecret(null)` проверка секрета отключена.
Отсутствующие заголовки передавайте пустыми строками.

`validateRequestBody()` проверяет, что тело непустое и его размер в байтах совпадает с Content-Length.
При нарушении выбрасывается `BadRequestException`. JSON разбирается отдельно через `MaxBot::makeUpdateFromString()`.

Имена заголовков и ключи глобального контекста доступны через константы `MaxBot`:

| Заголовок              | Константа имени заголовка       | Константа ключа `$_SERVER`          |
|------------------------|---------------------------------|-------------------------------------|
| `Content-Type`         | `MaxBot::CONTENT_TYPE_HEADER`   | `MaxBot::CONTENT_TYPE_SERVER_KEY`   |
| `Content-Length`       | `MaxBot::CONTENT_LENGTH_HEADER` | `MaxBot::CONTENT_LENGTH_SERVER_KEY` |
| `X-Max-Bot-Api-Secret` | `MaxBot::SECRET_HEADER`         | `MaxBot::SECRET_SERVER_KEY`         |

Константы `*_HEADER` используйте для чтения HTTP-заголовков, а `*_SERVER_KEY` — для `$_SERVER` и окружения CGI.

#### Запрос из PSR-7

Если приложение работает с объектом запроса (`Psr\Http\Message\ServerRequestInterface`),
вместо чтения глобального контекста используйте `handleFromRequest()`:

```php
use MaxMessenger\Bot\MaxBot;

$bot = new MaxBot('your-access-token', 'your-secret', useRussianTrustedCaCertificates: true);

// Добавление обработчиков

$bot->handleFromRequest($request);
```

Тело запроса без обработки обновления отдаёт `readRequestContent()` — аналог `readRequestContentFromGlobal()`:

```php
$body = $bot->readRequestContent($request);
```

Оба метода выполняют те же проверки, что и версии для глобального контекста: метод, тип содержимого,
наличие и совпадение `Content-Length`, а также секрет.

Пакет `psr/http-message` не входит в зависимости SDK — установите его (обычно он уже есть вместе
с вашим HTTP-фреймворком), если используете эти методы.

## Сохранение и восстановление обновлений

Для отложенной обработки сохраняйте исходные данные **обновления**. Объекты `Update` и **события бота**
не следует передавать в `serialize()`. При восстановлении создавайте обновление через `Update::newFromJson()`
или `Update::newFromData()`: эти методы выбирают класс обновления по полю `update_type`.

Если у вас есть **событие бота** `$event`, получите **обновление** из свойства `$event->update`.

### JSON-строка

Обновление реализует `JsonSerializable`, поэтому его можно передать непосредственно в `json_encode()`.
Метод `jsonSerialize()` вернёт исходные данные обновления. Сохраните строку `$json` в выбранное хранилище,
а перед восстановлением прочитайте её оттуда.

```php
use MaxMessenger\Bot\Model\Response\Update;

// Сериализация исходных данных обновления в JSON.
$json = json_encode($update, JSON_THROW_ON_ERROR | JSON_UNESCAPED_UNICODE);

// Восстановление обновления из сохранённой JSON-строки.
$restoredUpdate = Update::newFromJson($json);
```

### Строка в формате сериализации PHP

В `serialize()` передавайте только массив исходных данных из `getRawData()`. Сохраните строку `$serialized`,
а перед восстановлением прочитайте её из хранилища. При `unserialize()` запретите создание PHP-объектов
через `allowed_classes`.

```php
use MaxMessenger\Bot\Model\Response\Update;

// Сериализация данных, а не объекта обновления.
$serialized = serialize($update->getRawData());

// Восстановление данных и создание обновления.
$data = unserialize($serialized, ['allowed_classes' => false]);
$restoredUpdate = Update::newFromData($data);
```

Восстановленное обновление можно передать боту с настроенными обработчиками:

```php
$bot->handleUpdate($restoredUpdate);
```

## Фильтрация обновлений

`MaxBot::handleUpdate()` перед созданием события бота вызывает фильтр обновлений. Калбэк получает `Update`:
`true` разрешает обработку обновления, возвращённый `Update` заменяет исходное обновление, `false` отклоняет обновление.
При отказе `handleUpdate()` возвращает `false`,
обработчики события бота не вызываются. Эта проверка также выполняется при получении обновлений через
`handleFromGlobal()`, `handleFromRequest()` и `handleFromServer()`.

В собственном фильтре можно логировать или сохранять пропускаемые обновления перед возвратом `false`,
например для последующего анализа или повторной обработки.

По умолчанию фильтр возвращает `$update->isValid()`: проверяет наличие ключей, перечисленных в
`getRequiredProperties()`, без проверки их значений и вложенных объектов. Общие поля `update_type` и `timestamp`
проверяются при создании `Update` и в этот список не входят.

Заменить фильтр можно через `setUpdateFilter()`. Например, чтобы обрабатывать только известные типы обновлений,
сохранив проверку обязательных полей:

```php
use MaxMessenger\Bot\Model\Response\Update;

$bot->setUpdateFilter(static fn(Update $update): bool => $update->isValid() && $update->getUpdateType() !== null);
```

`getUpdateFilter()` возвращает текущий калбэк. Отключить фильтрацию можно так:

```php
$bot->setUpdateFilter(null);
```

Фильтр может вернуть новое обновление, например после исправления или дополнения данных:

```php
$bot->setUpdateFilter(static function (Update $update): bool|Update {
    $data = $update->getRawData();
    $data['timestamp'] = max(0, $data['timestamp']);
    $replacement = Update::newFromData($data);

    return $replacement->isValid() ? $replacement : false;
});
```

Возвращённое обновление не проходит фильтр повторно. Оно определяет тип события и передаётся его обработчикам.
При ошибке после замены глобальный обработчик ошибок также получает новое обновление.

`makeEvent()` и `handleEvent()` фильтр не вызывают. При ручном создании событий бота проверьте обновление явно:

```php
$update = MaxBot::makeUpdateFromString($body);
$filter = $bot->getUpdateFilter();
$filterResult = $filter === null ? true : $filter($update);
if ($filterResult === true || $filterResult instanceof Update) {
    $event = $bot->makeEvent($filterResult instanceof Update ? $filterResult : $update);
    $bot->handleEvent($event);
}
```

## Продвинутая обработка обновлений

> Этот раздел для опытных разработчиков

### Способы обработки

Вы можете сделать процесс обработки **обновлений** более прозрачным и добавить собственную функциональность
на любом этапе. Для этого существует ряд методов:

- Методы для **Webhook**:
    - **MaxBot::handleFromGlobal()** — Запускает процесс обработки **обновления** полученного из глобального контекста.
    - **MaxBot::readRequestContentFromGlobal()** — Читает содержимое запроса из глобального контекста.
    - **MaxBot::handleFromRequest()** — Запускает процесс обработки **обновления**, полученного из PSR-7 запроса.
    - **MaxBot::readRequestContent()** — Читает содержимое PSR-7 запроса.
    - **MaxBot::validateRequestHeaders()** — Проверяет метод и заголовки запроса при самостоятельной обработке Webhook.
    - **MaxBot::validateRequestBody()** — Проверяет, что тело непустое и его размер совпадает с Content-Length.
    - **MaxBot::makeUpdateFromString()** — Создаёт объект **обновления** из JSON-стоки.
- Методы для **Long Polling**:
    - **MaxBot::handleFromServer()** — Получает **обновления** с сервера и запускает процесс их обработки.
      Ответ содержит маркер, который нужно использовать в последующих запросах.
    - **MaxApiClient::getUpdates()** — Получает **обновления** с сервера.
      Ответ содержит маркер, который нужно использовать в последующих запросах.
- Общие методы:
    - **MaxBot::handleUpdate()** — Проверяет **обновление** фильтром, создаёт объект **события бота** и запускает
      его обработку.
    - **MaxBot::makeEvent()** — Создаёт объект **события бота** на основе объекта **обновления**.
    - **MaxBot::handleEvent()** — Запускает процесс обработки **события бота** ранее добавленными обработчиками.
    - **MaxBot::handleEventUseHandlerList()** — Обрабатывает **событие бота** переданным списком обработчиков.
    - **BaseEvent::handle()** — Обрабатывает **событие бота** заданным обработчиком.

### Этапы обработки обновлений при использовании бота

- Сначала нужно получить **обновления** с сервера через API или из текущего запроса.
- **Обновление** может быть обработано немедленно или сохранено где-либо и обработано позже.
- `MaxBot::handleUpdate()` проверяет **обновление** настроенным фильтром, если он не отключён.
  При отказе фильтра обработка обновления завершается до создания события бота.
- Из **обновления** создаётся объект **событие бота**.
  Каждому типу **обновления** соответствует отдельный класс **события бота**.
  Объект **события бота** реализует вспомогательные функции для работы с обновлениями.
- **Событие бота** может быть обработано:
    - Обработчиками бота (методы `MaxBot::handleFromGlobal()`, `MaxBot::handleFromRequest()`,
      `MaxBot::handleFromServer`, `MaxBot::handleUpdate()`, `MaxBot::handleEvent()`).
    - Своим списком обработчиков (метод `MaxBot::handleEventUseHandlerList()`).
    - Своим обработчиком (метод `BaseEvent::handle()`).
