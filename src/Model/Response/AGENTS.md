# Соглашения для моделей ответов

Сверяй модель со схемой `schemas/schema.yaml` и похожими классами в этой папке. Примеры: `Button`, `Chat`,
`Attachment`.

## Создание моделей

- Создавай модели через унаследованные от `BaseResponseModel` методы `newFromData()`,
  `newFromNullableData()`, `newListFromData()`, `newListFromNullableData()` и `newList2DFromData()`.
  Не дублируй эти методы в дочерних классах.
- Для списков перечислений используй `tryFromList()` и `tryFromNullableList()` из `EnumHelperTrait`.
  Подключай трейт к перечислению, если нужны эти методы.
- Переопределяй `newFromData()` только для выбора дочернего класса по `discriminator`, как в `Button`.
  Оставляй базовый класс конкретным, чтобы он мог представить неизвестное значение.
- При переопределении проверяй `static::class !== self::class`, чтобы вызов из дочернего класса
  не зациклился. Аннотируй входной `$data` только по полям, нужным для выбора класса.

## Данные и методы

- Описывай собственные поля `$data` как array shape без унаследованных полей. Отсутствующие поля обозначай `?`.
  Массивы описывай как `list`; типизируй их элементы и значения `additionalProperties`.
  Вложенные объекты описывай как `array`, не раскрывая их внутреннюю структуру через array shape,
  в том числе в списках и значениях `additionalProperties`.
- Не добавляй в новые модели `deprecated` поля.
- Сервер не передаёт `null` в полях ответа: вместо этого поле отсутствует, даже если схема или документация
  допускает `null`. В `$data` описывай такие поля необязательными ключами (`field?: Type`), без `|null`.
  Геттер может возвращать `null`, если поле отсутствует.
- В `MessageCallbackUpdate` сохраняй `message` обязательным вопреки схеме и документации.
  Это принятое в проекте исключение: обновления без сообщения не проходят `isValid()`.
- В `OpenAppButton` поле `web_app` может отсутствовать в ответе, несмотря на `required` в схеме.
  В модели запроса это поле обязательно.
- Для логических свойств используй `is...()` вместо `get...()`.
- Для времени добавляй `get...Raw()` рядом с методом, возвращающим дату, как в `Chat`.
  Для перечисления и `discriminator` добавляй `get...Raw()` рядом с методом, возвращающим enum.
  Не подставляй значение enum по умолчанию для неизвестного значения API.

## Типы и документация

- Сохраняй ограничения схемы, которых нет в типах PHP: `non-empty-string` при `minLength > 0`,
  `non-empty-list` при `minItems > 0`, числовые диапазоны. Для Unix timestamp используй
  `non-negative-int`, в том числе внутри array shape.
- Ограничения длины и числа элементов, не выраженные типом, помещай в скобках в конце первого предложения
  описания значения в `@return`. `minLength: 1` и `minItems: 1` уже выражены типами.
- Для `discriminator` используй `non-empty-string` в `$data`, когда ответ API гарантирует непустое значение.
